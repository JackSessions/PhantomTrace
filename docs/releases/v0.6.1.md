## PhantomTrace v0.6.1: the new look

**A read-only NTFS consistency checker for DFIR.** NTFS describes the same disk in several places. Honest activity keeps those descriptions in agreement; tampering (and corruption) often doesn't. PhantomTrace reads a raw image or device, never writes to it, and reports where the layers disagree.

```bash
pipx install phantom-trace-ntfs
phantom-trace --gui                    # point-and-click, in your browser
phantom-trace disk.img --html report.html
```

### What's new

- **A new look** for the GUI and the HTML report: frosted glass over a night-security backdrop, Google colours, a four-colour shield, glowing rainbow-ring buttons, a DFIR field note, and a clickable findings table with a volume map. It respects the reduced-motion setting.
- Package name, commands and checks are unchanged (`phantom-trace-ntfs`, `phantom-trace`, `phantom-trace-gui`). 0.6.0 on PyPI has the same checks with the earlier plain look, so upgrade with `pipx upgrade phantom-trace-ntfs`.

### What it checks

| Check | Compares | Why it matters |
|---|---|---|
| `mft_flag_vs_bitmap` | A record's "in use" flag vs the `$MFT` record bitmap | Hidden or resurrected entries, edited MFT, crash damage |
| `clusters_free_in_bitmap` | Clusters a file's runs claim vs the volume `$Bitmap` | Bitmap altered to hide data, or corruption |
| `cross_allocated` | Two records claiming the same cluster | Manual run-list edits or serious damage |
| `run_out_of_bounds` | A data run outside the volume | Invalid or forged run list |
| `bad_fixup` | MFT update-sequence verification | Torn, corrupt or hand-edited records |
| `mirror_mismatch` | First MFT records vs `$MFTMirr` (low confidence) | Worth a look; crashes can cause it too |

Plus optional, weaker timestamp checks (`--heuristics`). Exit codes: `0` clean, `1` findings, `2` error.

### Honest limits

- It reports **inconsistencies, not proof**. They can come from tampering, corruption or a live system that was still writing. Verify with a second tool (The Sleuth Kit, MFTECmd) before drawing conclusions.
- The test suite builds real NTFS volumes with the `ntfs-3g` tools, tampers with them on purpose, and checks that clean volumes stay quiet. Volumes formatted and used by Windows, and real-world anti-forensic tools, are not yet covered. If you hit a false positive or a miss, please open an issue: those reports are the most valuable.
- Fragmented `$MFT` with an `$ATTRIBUTE_LIST`, compressed streams, `$LogFile` and `$UsnJrnl` analysis are not implemented yet.
